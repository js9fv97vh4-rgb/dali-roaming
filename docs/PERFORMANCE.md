# 3D 性能记录 · 2026-10-18

## 本次改动

1. `map3d-mesh.js` 分离纯几何生成，`map3d-worker.js` 在后台执行，`map3d-builder.js` 负责转移数组、超时、失败降级及清理。模块 Worker 不可用时仍使用同样的几何算法。线程在街巷完成或加载失败后终止。
2. 原岸线距离场对 96 × 160 个像素逐一扫描 1,166 条边（约 1,791 万次距离计算）。新算法按每条边的 1.5 公里影响范围更新平方距离，最后每像素只求一次平方根；最终 15,360 个字节与旧结果一致。单独 Node 五次测量中位数约 502 → 0.56 ms，该数字仅代表此算法，不能等同于网页总加载时间。
3. 同类地表合并绘制，三塔用两个实例网格代替 54 个独立网格。没有减少地形分辨率、道路、建筑或岛屿数量。
4. 稳定视角不再逐帧重排 DOM 标签；相同行程复用路线几何。海岸照片布局、投影向量和遮挡弹窗节点复用。
5. 漫游界面和镜头约 30 帧更新，时间仍按每帧实际间隔累计。时间文本按秒更新，无障碍站点说明只在换站时更新；手动换图不改变播放或暂停状态。

## 测量方法

在同一台电脑的独立无头 Chrome 中，对优化前源文件副本和最终代码分别运行三次全新页面加载。使用 1280 × 900 视口、DPR 1、4 倍 CPU 限速、禁用缓存、本地 HTTP 服务；外部照片请求被阻止，以减少远端网络波动。GPU 为无头测试配置，非实体手机。下列结果是三轮中位数，原始记录见 [JSON](performance-20261018.json)。

“首次绘制”记录首个 WebGL 绘制调用；“街巷就绪”记录道路、建筑加入场景的状态变化。主线程阻塞合计为观察窗口内所有 long task 超过 50 ms 的部分；绘制调用量在加载完毕后采样一秒。CPU 限速不代表任何特定手机型号。

| 指标 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| 首次 WebGL 绘制 | 2,504 ms | 632 ms | 减少 75% |
| 街巷细节就绪 | 2,952 ms | 854 ms | 减少 71% |
| 主线程累计阻塞 | 2,153 ms | 146 ms | 减少 93% |
| 稳定运行绘制调用 / 秒 | 约 5,749 | 约 1,468 | 减少 74% |

这是本地 CPU 与绘制开销对比，不包含 GitHub Pages 下载速度或实体设备上的 GPU、温度及网络差异；首次 WebGL 调用也不等于所有像素已经呈现到屏幕。

## 正确性与兼容检查

- 51 项 Node 测试与 `npm run build` 通过。
- 使用优化前的完整网格生成摘要核对地形顶点、索引、颜色、法线、浅水纹理、道路、建筑及各类地表三角形；保留完整 401 × 449 高程网格。
- 真实 Worker 转移结果与兼容构建结果一致；线程不可用、加载失败、消息发送失败、超时和销毁均有覆盖。
- 独立浏览器的 390 × 844、DPR 3 手机尺寸下，S 湾直接进入、播放中手动换图、暂停后换图、全景／夜景／探索切换均通过；页面无横向溢出、无脚本异常。静止镜头下标签零重复属性更新，操作镜头后正常更新。
- 本次未在实体手机或 Safari 上进行新一轮性能测量。

以后更换地理源数据或 Three.js 版本时，需要先审核对应画面，再更新 `tests/fixtures/map3d-mesh.json` 的几何基准；不得仅为绕过失败而重新生成摘要。


## 全景与图片专项复查

上面的首次加载数据不能代表全景持续运行和外链图片的实际体验。后续复查发现，全景仍由水波驱动约 30 帧／秒持续绘制，小尺寸卡片还会下载 960 像素缩略图及部分 0.4–1.3 MB 的外链原图。

已将全景改为交互触发重绘，全屏缓冲限制为 120 万像素；移除全景控制条的背景模糊和引线阴影滤镜。日常探索、漫游和夜景仍保留原动态行为。许可照片提供 240 像素站内预览；15 个默认预览中 14 个为站内资源，凤阳邑为已实际验证的 320 像素原站缩略图。图片队列最多 3 个并发，去重缓存，8 秒超时，失败时显示状态，重开全景可重试。

在独立 Chrome、1440 × 1000、DPR 2、4 倍 CPU 限速下，另加 150 ms 网络延迟及 192 KB/s 下载限速，全景 15 个可见图片均正常载入；静止一秒实测 0 次 WebGL 绘制。未在实体设备上据此推断具体帧率。

## 加载预览与入口模型 · 2026-10-24

- 初始云南首页不请求三维引擎、地形或细节。进入洱海后才并行预加载 Three.js 核心与模块，随后初始化共享场景。
- 约 90 KB 的真实渲染截图始终显示到首个 WebGL 绘制成功。进度来自引擎、地形下载、几何构建和首帧阶段；地形按实际读取字节更新。压缩响应不将压缩体积误当作解码后字节总量。时间区间根据本次阶段耗时与当前浏览器成功加载历史估算，无法可靠估算时不显示倒计时。
- WebGL 丢失、恢复与最终失败均保留可理解的状态；全景、夜景和漫游移动同一加载提示。
- 远景采用原始顶点的隔行索引，地形面数降至完整网格的四分之一；近景由原生 Three.js LOD 恢复完整索引，边界角点、地形数据和地理位置不变。
- 景点圆点使用一个实例网格，引线使用一个线段批次；三种入口模型使用四个材质批次，不引入外部模型下载。空闲探索水纹采用较低绘制频率，交互和漫游保持原有节奏，全景继续按需绘制。
- 本地服务器返回资源长度、ETag 与 Last-Modified，重复请求可以返回 304；修改文件后仍需重新验证，不会固定缓存旧版。

独立 Chrome 检查采用 1280 × 1000、DPR 1、SwiftShader 软件渲染，外部图片请求被阻止。检查通过：云南首页零提前三维请求、加载截图与进度、三种入口模型、全景／夜景切换、390px 无横向溢出、真实 WebGL 丢失与恢复、远近景切换、地形的条件请求返回 304。没有捕获到应用脚本异常。

同一检查配置下，合并点位前后每次场景绘制约为 50 → 19 个 WebGL 绘制调用。此数仅说明绘制批次减少；软件渲染的短时帧率不代表实际 GPU、实体手机或 Safari 的性能。没有据此承诺固定帧率。
